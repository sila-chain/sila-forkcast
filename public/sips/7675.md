## Abstract

This Meta SIP lists Core SIPs introducing changes to Sila's consensus which were activated independently of an Sila hard fork due to their backward compatible nature. These SIPs generally introduce constraints to underspecified protocol rules  or clarify how certain edge cases should be handled. 

## Motivation

To maintain consensus across all nodes, backward incompatible changes to Sila must be activated synchronously. Given the coordination required for this, changes are usually bundled together in network upgrades. A Meta SIP is typically used to list the changes included in a network upgrade, as well as its activation time.

However, backward compatible consensus changes do not require a network upgrade to be activated. For example, if a consensus rule is underspecified, an SIP can propose a constraint to bound it. If the constraint was never broken in Sila's history and is unlikely to be broken in the future, the SIP can be considered backward compatible. It could then be "retroactively activated", as both nodes which support the change and those which do not would agree on the current network state and history. 

This Meta SIP lists all such SIPs which core developers have retroactively included as part of the Sila protocol specification. 

## Specification

### Retroactively Activated SIPs 

* [SIP-2681](./sip-2681.md): Limit account nonce to 2^64-1
* [SIP-3607](./sip-3607.md): Reject transactions from senders with deployed code
* [SIP-4803](./sip-4803.md): Limit transaction gas to a maximum of 2^63-1
* [SIP-7523](./sip-7523.md): Empty accounts deprecation
* [SIP-7610](./sip-7610.md): Revert creation in case of non-empty storage

### Activation 

All SIPs listed above are considered activated as of Sila's genesis block. Note that SIP-7523 distinguishes pre- and post-merge behavior on the Sila sila-mainnet. 

## Rationale

This Meta SIP provides a global view of all changes included in the Sila protocol without an explicit network upgrade, as well as links to full specification.
